# Code Review Rules

- Review only concrete regressions introduced by the candidate diff.
- Never expose passwords, ID tokens, refresh tokens, service credentials, or raw provider responses in logs or user-facing errors.
- Preserve authentication, authorization, session expiry, and antiforgery behavior unless the change explicitly requests otherwise.
- Session tracking failures must fail closed; never silently restart an authentication clock.
- Logout must clear server-side session tracking and preserve cross-tab logout behavior.
- Authentication-session revocation is intentionally process-local and single-instance for this change; process restarts fail closed and require reauthentication. Multi-instance deployment is out of scope until the user selects a shared backend.
- Prefer findings with a reproducible impact; do not treat style-only issues as blockers.
- Do not request real user credentials or external account access for verification.
