T21 implementation is done; its final commit remains pending. Historical results and failures below remain recorded as such.

The theme control is a two-state `<button role="switch" data-theme-toggle>` with inline SVG sun and moon icons (no dropdown, no third "system" option). Clicking toggles between light and dark and saves `'light'` or `'dark'` in `localStorage` under the key `theme`.

**Initial state logic** (runs synchronously before paint):
1. If `localStorage` holds `'light'` or `'dark'`, that explicit preference is applied and OS changes are ignored until the next click.
2. Otherwise (`'system'`, any unknown value, absent, or storage blocked) the OS preference is followed via `matchMedia('(prefers-color-scheme: dark)')`, falling back to light if `matchMedia` is absent or throws.

The sun icon (`block dark:hidden`) reflects the current **light** state; sol is current light. The moon icon (`hidden dark:block`) reflects the current **dark** state; moon is current dark. Both SVGs carry `aria-hidden="true" focusable="false"`; the button carries `aria-checked` (updated by JS) and `aria-label="Cambiar tema: modo claro/oscuro"` for screen reader support. The button has a 44×44 px click target, visible focus ring (`focus:ring-2`), and matches the project's dark-aware hover colours. Space and Enter activate the toggle because it is a native `<button>`.

The partial `Views/Shared/_Layout.cshtml` and `Views/Login/Index.cshtml` both include `_ThemeSelector.cshtml`. CSS classes `dark:block` and `dark:hidden` require a `npm run build:css` run after the first inclusion of the new partial.

---

The `'light'` or `'dark'` preference is shared between login and the application using `localStorage` (`theme`). Without a valid preference, the OS setting is followed; if storage is blocked, the in-memory choice lasts until reload. The local script runs before stylesheets to apply the initial theme. Light mode is saved as `'light'`; dark mode is saved as `'dark'`; both persist across reload.
